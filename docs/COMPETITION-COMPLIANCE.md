## 3. 核心技术要求

### 3.1 权限分级机制（赛题优先级：高）

等级由纯函数策略引擎 `server/policy/engine.ts` 判定：从工具声明的基础等级出发，规则**只能升级或拒绝**；用户确认时在执行锁内重新判级；扣款事务内再核一次日累计（本人互转除外）。详见 [SECURITY.md §3](SECURITY.md#3-权限分级)、算法见 [ALGORITHMS.md §1](ALGORITHMS.md#1-风险分级策略引擎)。

**转账的黄 / 红界限沿用赛题示例**：北京时间自然日、本人全部账户**转给他人**的累计（含本笔）**≤ 1000 元为黄色，> 1000 元为红色**；恰好 1000 元仍为黄色。答疑确认 1000 元只是示例、可由产品自行设定，且本人账户互转一般不计入额度，因此本人账户、本人银行卡之间互转和信用卡还款不计入累计、也不触发这条规则。早期版本另有"夜间单笔超过 500 元""7 天内新增收款人"两条升红规则，已于 2026-10-13（`0d547d4`）移除，此后转账分级只看日累计。

| 赛题等级 | 赛题示例 | 文财实现 | 状态 |
|---|---|---|---|
| 🟢 绿色 · 自动执行 | 余额、交易记录、账单分析、理财收益查询 | 所有只读工具（`kind: 'read'`）为绿色，直接执行；测试保证没有写工具是绿色 | ✅ |

**在赛题分级之上的补充，答辩时主动说明**（都不改变 1000 元的黄 / 红界限）：

1. **黄色转账也需要一次付款凭证。** 赛题的黄色只要求"确认"；文财在已注册用户动用银行卡或资金账户时，确认后还要求交易密码、短信、模拟指纹或人脸**任选其一**。理由是卡密码属于支付凭证，确认按钮只能证明"看过"，不能证明"本人同意动用这张卡"。等级本身仍是黄色。
2. **红色内部的验证组合**：单笔超过 3000 元（此时日累计必然已超过 1000 元，本来就是红色）或收款账户被标记可疑时，第二步只接受模拟指纹 / 人脸，不接受短信。这只改变红色的验证方式，不新增等级。
3. **诱导转账三层识别与冷静期**：关键词、行为画像（与本人平时转账习惯比较）、模型判断话术三层识别，命中时转给他人的操作升为红色，确认单强制展示劝阻提示（含 96110），用户勾选已核实后才能验证。话术命中、用户仍坚持确认的转账进入 24 小时冷静期，期间可撤销，并生成后台回访工单。只升级不拒绝。
4. **按风险事实升级或拒绝**：收款账户被 AI 标记可疑升红、被人工确认高危直接拒绝；10 分钟内 5 笔转账熔断；商城单笔超过 3000 元或开启自动续费升红；账户锁定期间拒绝非只读操作。

**渠道能力上限**：Web/H5 可到红色；飞书到黄色，超出时跳转 H5；MCP 只读。

### 3.2 安全机制（赛题优先级：高）

|---|---|---|---|
| **幻觉防护**：不得编造交易结果或账户信息 | 余额、确认单、回执、理财建议走服务端数据渲染的固定组件；模型正文先缓存、核验后再发送：金额与卡尾号必须能在服务端证据中找到出处，流水的日期 / 金额 / 尾号必须来自同一笔，没有成功回执的"已完成"说法被替换；生成式界面禁止数字字面量 | ⚠️ 数字核验暂不识别"万"和中文数字 | SECURITY §7、ALGORITHMS §4 |

| **操作审计**：完整的决策链路与执行日志 | 用户输入、审核判定、工具调用、策略判定（含命中规则与当时事实）、确认、执行、补偿、注入清洗、输出核验、熔断、后台命令全部写入哈希链审计；后台"安全内核"页可追踪单次请求的完整决策链 | ⚠️ 哈希链未加密钥，只能发现直接篡改 | SECURITY §10、§16 |

### 3.3 意图理解与任务规划

| 赛题要求 | 文财实现 | 状态 |
|---|---|---|
| 模糊表达、省略上下文、隐含意图 | 模型工具循环（最多 8 步）；缺失条件用即时生成的问卷补齐，真实对象（卡、收款人）用选择组件；收款人、银行卡按名称 / 备注 / 尾号消歧，多候选必须让用户选 | ✅ |
| 复杂任务拆解为子任务 DAG | `plan_task` 提交 1–12 个节点的 DAG：校验节点、工具白名单、依赖存在、`$ref` 只引用直接依赖、无环后拓扑执行 | ✅ |
| 执行中断 | 对话停止按钮把中止信号传到执行器，计划停在两个节点之间并保存为"已暂停"；任务中心可暂停、恢复、取消 | ✅ |
| 回退 | 失败或取消时逆序执行已完成写操作的补偿动作；缺少补偿或补偿失败时进入"失败"并转人工，不谎报回滚成功 | ✅ |
| 人工接管 | `handoff` 节点转人工；任务中心记录人工处理结果后继续，人工备注不能替代银行回执；后台可人工复核风险标记 | ✅ |

算法见 [ALGORITHMS.md §3](ALGORITHMS.md#3-任务-dag-执行与补偿)。

## 4. 演示边界（如实表述）

- 指纹 / 人脸为**模拟按钮**，界面明确标注，不采集生物特征；验证触发条件与"密码 + 生物验证"组合由代码强制执行。

- 对外表述统一按 [SECURITY.md §20](SECURITY.md#20-对外表述口径)：不说"零幻觉""防住所有注入"。
