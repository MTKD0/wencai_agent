> 目标：**在 5 分钟内让评委记住一件事**——"LLM 只提议，代码才授权"。

## 一、录制前必做：先解决"红色操作能不能做完"

**比赛演示使用模拟指纹 / 人脸按钮，不采集生物特征。** 在 `.env.local` 中显式设置；部署到现场服务器时，也要在服务进程的环境变量中设置并重启：

```dotenv
AUTH_DEMO_MODE=true
```

| 启动方式 | 未显式设置时 | 演示准备 |
|---|---|---|
| `start.bat` / `start.sh` / `pnpm dev`（开发模式） | 非 production 默认开启 | 仍显式设置，避免依赖默认值 |
| 生产构建以 `NODE_ENV=production` 运行 | 默认关闭 | 比赛演示部署必须显式开启；构建后不能假定运行进程会自动加载 `.env.local` |

当前验证流程（以独立安全页面和服务端规则为准）：

| 场景 | 所需验证 |
|---|---|
| 最终为黄色的常规转账（日累计含本笔 ≤ 1000 元，无其他红色原因） | 付款卡交易密码、绑定手机短信、模拟指纹、模拟人脸任选一种 |
| 日累计含本笔 **严格超过 1000 元**，或 AA 付款等基础红色操作 | 有银行卡时，先验证卡密码，再完成短信或模拟指纹 / 人脸额外验证；无卡且不要求双重验证时可用强验证方式验证资金账户 |
| 单笔 **严格超过 3000 元**，或收款账户标记为 `suspected` | 付款卡交易密码 **加** 模拟指纹或模拟人脸；第二步不接受短信或 Passkey |
| 收款账户标记为 `confirmed` 高危 | 拒绝执行，不因开启演示模式而放行 |
| 未绑定银行卡的独立资金账户，常规转账 | 短信、模拟指纹或模拟人脸；未配短信时使用模拟按钮 |

没有银行卡密码的独立资金账户不能凭空完成异常转账的密码因子；开启演示模式也不会解除此限制。其他敏感操作按独立页面完成额外验证。

**录制前必须彩排**：一笔黄色转账；今日已转 800 元后再转 300 元；一笔 AA 付款；一笔 3001 元转账；向 `suspected` 演示收款账户转账。累计恰好 1000 元不因累计规则升级，超过才升级；累计跨本人所有付款账户，以 UTC+8 自然日计算。3001 元及 `suspected` 转账应先输入对应尾号卡片的交易密码，再直接点击指纹或人脸按钮。设置 `AUTH_DEMO_MODE=false` 时模拟按钮不可用；不能改用 Passkey 或短信完成这条指定生物因子的双重验证链路。

短信是可选演示方式，需要配置 `SMS_DELIVERY_URL`（接收 `POST {phoneNumber,code,...}` 并返回 2xx）；交易验证短信不会用日志验证码代替。无需为了当前指纹 / 人脸演示预先在 `/settings` 注册 Passkey。

建议答辩表述：

> 强验证的触发条件和“密码 + 生物验证”的组合要求由服务端策略与确认链路强制执行。演示环境用明确标注的模拟指纹 / 人脸按钮代替设备采集，不声称进行了真实生物识别。项目保留 WebAuthn Passkey 实现，后续可对接设备验证或银行活体检测 SDK；真实凭据必须完成服务端校验及方式映射后才能接入现有链路。当前 Passkey 不能直接充当异常转账的第二因子，设备验证也不能可靠证明用户采用的是指纹、人脸还是设备 PIN。

正式业务应关闭模拟验证并完成真实验证对接，不能把生产构建的演示部署描述为已具备真实生物识别能力。

同时确认数据与启动方式：

```bash
# 1. 干净数据（会清空并重建演示数据）
pnpm db:reset

# 2. 启动（Windows 双击 start.bat 即可，它会同时启动 worker）
pnpm dev
```

`start.bat` 会同时启动 Web 与 worker（10 秒轮询定时任务）。**没有 worker，订阅提醒和生日订单不会触发。**

## 二、录屏方法

### 2.1 工具选择

| 系统 | 推荐 | 备选 | 备注 |
|---|---|---|---|
| **Windows** | **OBS Studio**（免费开源） | Xbox Game Bar（`Win + G`） | Game Bar 只录单个应用窗口，切浏览器标签会断；OBS 更稳 |
| macOS | QuickTime Player（文件 → 新建屏幕录制） | OBS | 系统自带，够用 |
| 手机端演示 | 系统自带录屏 | scrcpy + OBS | 需要展示移动端时用 |

**OBS 关键设置**（Windows）：

- 输出 → 录像格式 `mp4`，编码器 `x264`，码率 `6000 Kbps` 以上
- 视频 → 基础/输出分辨率都设 `1920x1080`，FPS `30`
- 音频 → 麦克风选对设备，**先录 10 秒试听**（回放确认没有电流声/爆音）
- 来源 → 添加「显示器采集」（全屏）或「窗口采集」（只录浏览器）

### 2.2 画面准备（这一步决定"看起来专不专业"）

1. **浏览器用干净窗口**：关掉所有其他标签、书签栏、扩展图标。
2. **缩放调到 110%**：默认 100% 在 1080p 视频里字太小，评委看不出细节。
3. **隐藏任务栏**：Windows 右键任务栏 → 任务栏设置 → 自动隐藏。
4. **关通知**：Windows 设置 → 系统 → 通知 → 关闭（否则录制中途弹出微信提醒就废了）。
5. **提前滚动预热**：首页、Agent 面板各打开一次再关掉，让数据和字体都加载完，避免录到 loading。
6. **演示用 1920x1080 的显示分辨率**，不要用带缩放的笔记本高分屏录完再放大。

### 2.3 分段录，别一镜到底

**强烈建议分段录制再拼接**。一镜到底意味着任何一个环节卡顿、模型多绕一步，整条就要重录。分段后：

- 每段 30–60 秒，只讲一件事
- 某段讲错了只重录那一段
- 剪辑时能砍掉模型"啰嗦"的中间步骤，节奏更快

**唯一例外**：涉及长链路的部分（如 DAG 挂起 → 确认 → 恢复），最好一镜到底，因为那是"连续性"的证明。

### 2.4 录完的检查清单

- [ ] 旁白音量稳定，没有说话时突然变小的段落
- [ ] 没有录到通知弹窗、书签栏、其他标签
- [ ] 模型回复的等待时间已被剪掉（或加"此处加速 ×2"角标）
- [ ] 视频总长 4–6 分钟（超过 8 分钟评委会疲劳）
- [ ] 结尾停在**安全内核页**，不是停在聊天界面

## 三、演示脚本

### 3.0 叙事主线（先定这个，再排分镜）

不要按"功能列表"演示，那会变成产品说明书。按**一条冲突线**演示：

> **"如果模型被完全劫持，这个系统会怎样？"**
>
> 先演示正常业务跑得多顺（1–4 幕），再**现场发起攻击**（第 5 幕），最后打开安全内核证明"每一步都拦得住、都留了痕"（第 6–7 幕）。

这样前面所有功能演示都在为最后一击蓄力，评委记住的是最后那个画面。

### 3.1 分镜表

总时长约 **5 分钟**。台词栏是**建议旁白**，不是逐字稿。

---

#### 第 0 幕 · 开场（0:00–0:20）

| 项 | 内容 |
|---|---|
| 画面 | 登录页 → 手机号 `13800000000` → 验证码（服务端日志里有）→ 首页 |
