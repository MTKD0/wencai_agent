# 文财 · 银行 AI 智能体

用自然语言办理银行业务的 AI 银行智能体。核心原则：**大模型负责理解与提议，确定性代码负责授权与执行。**

用户端、Agent 面板与管理后台基于 **shadcn / Base UI + Motion** 构建，保留文财蓝白视觉；组件架构与动效复用方式见 [UI 迁移说明](docs/UI-MIGRATION.md)。Windows 双击 [start.bat](start.bat)，或运行 `pnpm dev`，即可启动网页、后台任务和实时日志。

系统架构图见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，核心算法见 [docs/ALGORITHMS.md](docs/ALGORITHMS.md)，赛题逐项对应、作品简介与提交材料清单见 [docs/COMPETITION-COMPLIANCE.md](docs/COMPETITION-COMPLIANCE.md)；**安全机制的完整说明、测试覆盖与已知缺陷见 [docs/SECURITY.md](docs/SECURITY.md)（安全自评报告）**；当前源码调用链、开发入口、Windows 启动步骤和待办见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)。**接手本项目请先读 [docs/HANDOFF.md](docs/HANDOFF.md)**：四条硬约束、代码地图、两类令牌的区别、已知的坑与当前优先级都在那里。演示或录屏前先看 [docs/DEMO.md](docs/DEMO.md)：分镜、固定话术、录屏方法与现场兜底。全部 30 份文档的分类与主次见 [docs/README.md](docs/README.md)。

## 快速开始

Windows 可直接双击根目录的 `start.bat`：自动加载 `.env.local`、检查依赖、启动服务并打开浏览器。启动窗口就是实时日志窗口，日志同时保存在 `.scratch/logs/`；按 `Ctrl+C` 停止服务。端口优先读取本地 `PORT`，未配置时为 3000；端口占用时自动顺延，并使用日志中显示的实际地址。

首次运行会从 `.env.example` 创建本地配置并生成签名密钥；填写 `DEEPSEEK_API_KEY` 后重启即可启用 Agent，默认模型为 `deepseek-flash`。只有数据库文件不存在时才自动建表并播种，已有数据库不会被重新播种。`.env.local`、数据库与日志均不上传 Git。

手动启动方式：

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env.local  # 填入至少 16 位的 CONFIRM_SECRET（生产环境至少 32 位）和模型配置
New-Item -ItemType Directory -Force data | Out-Null
pnpm exec node --env-file=.env.local ./node_modules/drizzle-kit/bin.cjs push
pnpm exec node --env-file=.env.local --import=tsx src/server/db/seed.ts
pnpm dev
```

以上适用于首次初始化；播种会重建演示数据。服务端从进程环境变量读取配置，上述命令显式加载 `.env.local`。环境变量已经注入时可直接使用下方快捷命令。

登录用手机号验证码。演示环境未接真实短信，下面两个演示账号、尚未注册的号码以及在演示环境里注册的号码，点「获取验证码」后登录页会直接显示并自动填入；其他已注册号码的验证码只在服务端日志和后台运行日志中：

## 常用命令

Google VM 的 HTTPS 演示部署、生产启动与日志操作见 [部署说明](docs/GOOGLEVM.md)。本机双击 `open-googlevm-logs.bat` 可查看云端文财项目实时日志；关闭日志窗口不会停止云端项目。

| 命令 | 说明 |
|---|---|
| `pnpm dev` | 启动 Web/H5、后台任务与实时日志 |
| `pnpm dev:web` | 仅启动网页（已有环境变量时使用） |

| `pnpm eval` | Agent 端到端任务评测：新建独立库，用真实模型执行 `eval/tasks.ts` 的 75 个任务，输出带分母和置信区间的完成率报告到 `eval/results/`（需配置模型密钥；可加 `--only=tr-01,bl-02`、`--scenario=transfer`、`--repeat=3`） |
| `pnpm redteam` | 红队统计：新建独立库，129 条注入语料（攻击与正常样本，含 27 条留出集）走真实输入审核，两个演示账户互相做越权实测，输出拦截率、误拒率与逐条结果到 `eval/redteam/`（不需要模型密钥） |
| `pnpm fraud-eval` | 诱导转账识别评测：55 条留出样本逐条经过关键词、行为画像、模型判断三层，输出识别率与误报率到 `eval/fraud/`（第三层需模型密钥；可加 `--repeat=3`） |
| `pnpm typecheck` | 类型检查 |
| `pnpm db:reset` | POSIX shell 下重建数据库并写入演示数据；Windows 见上方步骤 |
| `pnpm bot:lark` | 启动飞书机器人（需 `LARK_APP_ID` / `LARK_APP_SECRET`） |
| `pnpm mcp` | 以 stdio 启动 MCP Server（仅只读工具） |

## 用户首页与可复用动效

登录后进入蓝白色银行首页：真实资产、收支、银行卡、最近交易，以及账户、生活、我的四个栏目。「问文财」悬浮入口可自由拖动，点击展开接近全屏的 Agent 面板，保留原有流式对话、工具查询和交易确认流程。

首页、Agent 工具结果和生成式视图共用 `src/components/ui/` 中的银行卡、纵向柱图、环形图、入场和金额组件：卡片前推、柱形逐条上升、圆环顺时针展开，支持悬停、点击、键盘聚焦与系统减少动态效果设置。复用方式见 [开发导读](docs/DEVELOPMENT.md#用户界面与动效复用)。

## 转账与收款人

首页点击“转账”，可选择已保存收款人或本人账户互转；账户栏目也提供转账和收款人入口。新增收款人支持完整手机号查找，或完整文财账号＋户名核对，选定账户后确认添加。转账先核对确认单，再在独立安全页面验证：当天转给他人的累计金额（含本笔）不超过 1000 元为黄色，付款卡密码、短信、模拟指纹或人脸任选一种；超过 1000 元为红色，先验证卡密码再完成短信或模拟指纹 / 人脸；单笔超过 3000 元或收款账户可疑时第二步只接受指纹 / 人脸。本人账户、本人银行卡之间互转和信用卡还款不计入累计；收款人新旧不影响等级。

文财系统内账户实时双边记账：A 扣款、B 入账，双方各有流水；“收款”可查看并复制本人的账号与户名。账号首次使用时自动生成并持久保存，已有数据库会无损增加扩展表。旧外部银行卡收款人仍为模拟转出，系统没有接入真实银行。

## 常用收货地址

生活商城「常用地址」可保存最多 10 个收货地址（家、公司、爸妈家等），下单时默认地址自动预填，点一下即可切换。Agent 下单前先查询常用地址：用户说“送到家里”或只有一个地址时直接使用，多个时让用户选择，不再要求重复输入；交给模型的手机号已脱敏，下单时由服务端按地址 ID 填入完整信息。用户在对话里给出新地址时，Agent 可在确认后代为保存。

## 银行运营管理后台

`/admin` 是给**银行工作人员**用的全行后台，不再是“选一个用户登录进去”。工作人员用工号和密码登录（账号由部署方通过 `ADMIN_STAFF_ACCOUNTS` 预置，仓库不存密码），回访结论、卡片冻结等操作都记录处理人。

- **工作台**：待回访工单（按冷静期到期时间排序、显示倒计时）、冷静期中金额、今日识别、累计保住资金与止付率、近 7 天识别趋势、三层识别各自的贡献。
- **反诈中心**
  - **回访工作台**：左侧队列、右侧工单详情——客户联系方式（默认脱敏）、资产与画像标签、识别依据（话术类别、模型引用的客户原话、行为信号）、本笔与客户平时的对比、回访核实清单；结论为确认诈骗并撤销、确认安全并放行（二次确认）、未联系上（记录联系次数）。
  - **识别事件**：每笔命中诈骗话术或行为异常的转账及其处理结果（待确认、劝阻后放弃、冷静期中、冷静期内撤销、冷静期后执行、已确认执行），点开看完整依据与处理经过。数据来自 `bank_fraud_events`（生成确认单时写入识别依据，结果在读取时由确认单与冷静期状态推出）。
  - **可疑收款账户**：原收款风险复核，实现见 [收款风险分析](docs/RECIPIENT-RISK.md)。
- **客户**：客户列表（按待回访、近期命中话术、画像需关注、账户锁定筛选）与客户详情（概况与画像、账户与卡、流水、理财、订阅与任务、反诈记录、操作审计）。客户详情全部只读，工作人员唯一的操作是**临时冻结 / 解冻卡片，须填写原因**。
- **安全与审计**：安全内核、运行日志。
- **演示控制**（仅演示模式）：推进业务时钟、执行到期任务，以及打开旧版单客户工作台代客户办理业务，用于准备演示数据。

**后台不能替客户动钱**：代客户转账、申购、开卡等命令只在演示模式下由服务端接受，正式配置下一律拒绝；所有命令写 `admin_command` 审计并记录处理人。

**访问控制**：`ADMIN_ENABLED` 总开关（生产默认关闭）；演示模式**不再免登录**。工作人员会话为签名 Cookie（8 小时，`HttpOnly`、`SameSite=Strict`），登录失败 10 分钟内超过 5 次即限流；脚本调用可用至少 24 位的 `ADMIN_TOKEN`；只有未配置 `ADMIN_TOKEN` 的本机开发环境可免登录。后台写接口统一校验请求来源。

**演示数据**：`pnpm exec tsx scripts/seed-customers.ts --append-demo` 追加 24 位合成客户与 12 个处于不同阶段的反诈案例（只追加、可重复执行，ID 以 `cust_` 开头）。

运行日志（`/admin?section=logs`）每 2 秒刷新本服务进程最近 500 条接口、登录认证、Agent 进度与关键错误；`AUTH_DEMO_MODE=true` 时可查看登录验证码（5 分钟后隐藏），现在只有登录的工作人员能看到。

## 工具层

银行工具注册表共 91 个工具（55 个 read、36 个 write）。实际 Web/飞书 Agent 暴露 90 个（55 个 read、35 个 write），其中旧 `request_password_change` 已从 Agent 白名单移除；MCP 只暴露 55 个只读工具。此计数不包含 `ask_questions`、`show_view` 等会话辅助工具，也不包含后台仿真控制。扩展部分采用**两段式确认**：

```
resolve_recipient → check_transfer_limit → preview_transfer（签发令牌，只读）→ commit_transfer（策略引擎拦截 → 用户确认 → 校验并消费令牌）
```

预览令牌绑定 操作类型 + 已解析实体 ID 的参数指纹 + 用户，15 分钟有效。改金额、换收款人、重放、跨用户、过期会被拒绝，见 `tests/confirmation-token.test.ts`；条件更新防止并发重复消费。用户确认另由 HMAC 待确认动作控制，默认有效期 300 秒。

多笔转账在统一选择界面确认后，由服务端按原始批次的收款人、金额和付款卡登记持久化顺序任务。第一笔验证成功后自动生成下一笔确认单，界面自动更新，无需手动输入“继续”；每笔仍单独确认和验证。重复点击同一批次只返回已有任务；取消后续转账不会撤回已完成的转账，剩余步骤停止。回执核对轮次仍只读，不开放模型交易权限。

Agent 问卷使用服务端保存的题目与结构化选项编号提交，保留原始业务上下文；题干与未选选项不作为转账指令。多笔任务的下一张确认单会显示在最新完成回执下方，历史任务区域保留状态。付款卡选择过滤信用卡与不可用储蓄卡，余额查询仍可浏览全部卡片。

`transfer` 与 `commit_transfer` 均已接入转账风险升级：转给他人的日累计超过 1000 元升级为红色；单笔超过3000元或可疑收款账户要求交易密码加指纹/人脸演示验证，确认执行前重新判定。AA 由参与人本人付款，不能由发起人登记到账；旧 `settleSplit` 实现已删除。飞书确认缺少银行卡/资金账户验证或需追加验证时，返回原确认单 H5 链接，登录同一账户完成独立安全验证后才能执行。其他实现边界见 [开发导读第 8 节](docs/DEVELOPMENT.md#8-当前实现边界与优先事项)。

## 用户与权限

- **身份**：手机号 + 验证码登录（better-auth + phone-number 插件），会话存库。未登录调用 `/api/dashboard`、`/api/chat`、`/api/confirm` 一律 401。
- **强验证**：在独立安全页面完成，模型不接触任何凭据。红色操作先验证付款卡交易密码（每卡独立，scrypt），再完成短信或模拟指纹 / 人脸；单笔超过 3000 元或收款账户可疑时第二步只接受指纹 / 人脸。连续失败 5 次锁定 30 分钟。
- **渠道绑定**：飞书账号需在 `/bind` 完成一次强验证后才可代办业务，未绑定账号查不到任何数据。
- **设备管理**：`/settings` 可查看并踢掉其他登录会话、解绑渠道、注册 Passkey。
